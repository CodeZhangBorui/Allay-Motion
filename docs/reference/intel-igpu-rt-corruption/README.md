# Intel 核显上渲染目标偶发被写坏：最小复现

这里是一个只用裸 WebGL2 的最小复现（不经过 Allay Motion 的引擎和 Three.js，不含任何素材：贴图都由代码生成），
用来证明“同一个静止场景反复渲染，偶尔有一帧和别的帧不同”是显卡驱动（或硬件）的问题，也可以拿去给 Intel 报问题、在新驱动上重测。
来龙去脉和全部实测记录见 `docs/decisions.md` 的“引擎确定性：Intel 核显上渲染目标偶发被写坏、8 位量化由引擎自己做”。

## 文件

- `rt-probe.js`：探针本身。经典脚本（不是模块），页面和 Worker 里都能用，定义全局函数 `allayRtProbe(options)`；选项和返回值写在文件开头。
  引擎测试宿主也用它（`tests/engine/harness/harness.ts` 的 `rtProbe`、`tests/engine/rt-probe.ts`）：探针看到不一致的机器上，逐字节的判定带理由跳过。
- `index.html`：运行探针的页面。

## 场景

照搬物品提示框（045）在 T-TPL-4 第 26 组随机参数（135 × 135 输出、界面缩放 1、16 个子帧）下出问题的那一帧，几何坐标和引擎记下的一样：

1. 每个子帧：`gl.clear` 清 270 × 270 的场景目标（带 24 位深度），再按顺序画一张九宫格底图、一张九宫格边框（16 × 16 纯色、带 mipmap 的 sRGB 贴图），
   然后五行“文字”（线性过滤的 sRGB 贴图，alpha 是固定种子生成的图案）。全部是 `SRC_ALPHA, ONE_MINUS_SRC_ALPHA` 混合，深度测试开、深度写关。
   框的下沿在第 245.25 行，最后一行文字的下沿在第 245.75 行（窗口坐标，原点在左下）。
2. 把场景目标 2 × 2 平均、乘 1/16 加进 135 × 135 的 RGBA16F 累积目标（`ONE, ONE` 混合）。
3. 16 个子帧之后把累积目标转成 RGBA8，读回整帧，算哈希。

场景完全静止，每一帧都应当逐字节相同。坏帧的样子：框下沿的一个像素，alpha 从 128 变成 131 或 135（一个子帧里多了 1 或 2 个超采样点），
颜色基本不变；把场景目标在子帧画完后直接读回，能看到在所有几何体之外（框下沿外 0.75 像素）的像素里出现了同一个 2 × 4 内存块里相邻行的数据。
偶尔也有完全不相干的颜色（例如 `0.255.176.255`）。

默认用最灵敏的配置：场景目标是 RGBA8、分配成 272 × 272（视口仍是 270 × 270）。`format: 'rgba16f', alloc: 270` 是引擎里的原样配置，也能复现，只是次数少得多。

## 怎么跑

- 浏览器：用 Chrome 或 Edge 直接打开 `index.html`（`file://` 也行，探针在主线程跑），选好参数后点“运行”。
  双显卡的笔记本要指定显卡：Chromium 的启动参数 `--force_low_power_gpu`（核显）或 `--force_high_performance_gpu`（独显），或者 Windows 设置里的“图形”首选项。
  页面上的“渲染器”一行可以确认实际用的是哪块。
- 引擎测试宿主：`pnpm test:engine` 每个 spec 开头跑一次探针（1.5 秒），结果打进测试输出（`[engine] 渲染目标探针：…`）。
  测试宿主默认用高性能显卡；`ALLAY_ENGINE_GPU=low-power` 改用核显，`ALLAY_ENGINE_ANGLE=d3d11-warp` 改用 WARP。

## 实测（2026-11-22，同一台笔记本：Intel 核显 + NVIDIA RTX 5070 笔记本独显，Electron 45.3.1 / ANGLE D3D11）

| 显卡 | 驱动 | 配置 | 结果 |
|---|---|---|---|
| Intel(R) Graphics（Arrow Lake，0x7D67） | 32.0.101.8424 | 默认（RGBA8、272），Worker，10 秒 | 3703 帧里 42 帧不同 |
| 同上 | 同上 | 默认，Worker，1.5 秒 × 10 次 | 10 次都看到了，每次 8–146 帧不同（每次约 500–600 帧） |
| 同上 | 同上 | 默认，每个 GL 调用之后查 `getError`（共 141,074 个调用），20 秒 | **0 个 GL 错误**，184 帧里仍有 7 帧不同 |
| 同上 | 同上 | RGBA16F、270（引擎原样），10 秒 | 3897 帧里 0 帧（这份代码生成的贴图下不灵敏；用引擎记下的原贴图重放时 4000 帧里 17 帧） |
| NVIDIA GeForce RTX 5070 Laptop GPU | 32.0.16.2101 | 默认，Worker，10 秒 | 8020 帧里 0 帧 |
| 同上 | 同上 | 每个调用后查 `getError`，5 秒 | 0 个 GL 错误，63 帧里 0 帧 |
| Microsoft Basic Render Driver（WARP） | 10.0.26100.9278 | 默认，Worker，1.5 秒 × 2 次 | 每次约 500 帧里 0 帧 |

调用序列是合规的：每个调用之后 `getError` 都是 0；每次绘制前都核对过采样的贴图不在当前帧缓冲上；用到的缓冲每次都清过或整个写过；
裁剪、模板、多边形偏移、覆盖率、抖动、剔除、颜色掩码、深度、混合等状态都在开头显式设好，不依赖默认值。

## 触发条件（用引擎记下的原样绘制在裸 WebGL2 里重放，Intel 核显）

“提示框”是上面那一帧（8 次绘制），每种 4000 帧；“88 个框”是测试夹具 `tests/fixtures/templates/partial-cover.js` 的一帧（616 次绘制），每种 1000 帧。
基线分别是 17/4000 和 28/1000。每行只改一项。

| 改动 | 提示框 | 88 个框 |
|---|---|---|
| 场景目标分配成 272 × 272（宽高按 8 或 16 取整） | 186 | 29 |
| 320 × 320（按 64 取整） | 12 | 31 |
| 512 × 512 | 11 | 45 |
| 3840 × 3840（只画左下角那一块） | 10/2000 | 12/500 |
| 不挂深度附件 | 7 | 25 |
| 深度 16 位 / 24 位 + 模板 / 32 位浮点 | 50 / 61 / 0 | 19 / 28 / 27 |
| 不写深度 | 93 | 23 |
| 文字贴图改最近邻过滤 | 0 | 8 |
| **关掉混合** | **0** | **0** |
| 不调用 `scissor`（裁剪测试本来就关着） | 143 | 23 |
| 用全屏绘制代替 `gl.clear` 清颜色和深度 | 0 | 29 |
| 场景目标改 RGBA32F | 0 | 18 |
| 放进 Worker 里跑 | 71 | 15 |

结论：**混合是唯一必要的条件**；对齐尺寸、深度、过滤、清屏方式、格式都只改变次数，换一种场景就不一定有用。同样的小场景画在 3840 × 3840 的目标上照样出现；
同样的两个场景放大到 1920 × 1080 输出（每次绘制覆盖的像素多 64 倍）时，在引擎里分别 1000 次和 600 次里 0 次。
