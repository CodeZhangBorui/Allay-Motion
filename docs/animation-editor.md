# 动画编辑器：设计说明

状态：第一期已实现（2026-11，用户 2026-11-15 的反馈清单要求“允许直接在软件里纯代码编辑模板和动画”，并要有“新建/编辑动画的地方”）。
相关：`docs/code-editing-and-mcp-plan.md`（解耦架构、H1–H12）、`docs/04-templates.md`（模板格式与运行时接口）、`docs/06-ui-design.md` 6.15（界面位置）、`docs/decisions.md`“2026-11 反馈：开发模式、代码编辑与动画编辑器”。

## 1. 目标与约束

**目标**：不写代码也能从零做一段转场或叠加动画——在时间轴上放方块、物品、文字、色块，打关键帧、选缓动、实时预览、导出视频；同时**任何时候都能直接改它的代码**，两边改的是同一份东西。做好的动画能变成一个普通的模板，进模板库、能分享。

**不变的约束**：

- 画面是时间的纯函数（硬性规则 2）。动画的解释器只按 `t` 插值，没有“上一帧”的状态。
- 动画在引擎 Worker 里跑，和内置模板、用户模板走同一条装载路径（规则 3、5）：交给引擎的就是一份“manifest + template.js”，template.js 只用公开的 `ctx` 接口。
- 不引入 Theatre.js 和 GSAP（规则 7）。下面借的只是概念。
- 界面风格与现有界面统一（`docs/design-direction.md`），这是用户唯一要求固定的东西。
- 内嵌代码编辑器是可选模块，拆掉后动画编辑器仍然完整可用（代码视图退回普通文本框）。

## 2. 调研：各家的做法，我们借什么

| 软件 | 核心概念 | 借什么 | 不借什么 |
|---|---|---|---|
| After Effects | 合成、图层、属性的秒表与关键帧、图表编辑器、表达式 | 图层列表 + 每层可展开的属性；属性行的“菱形”在当前时刻加删关键帧；有关键帧的属性改数值时自动落关键帧；“定格关键帧”（我们叫“保持”） | 表达式语言（我们的“表达式”就是模板代码本身） |
| Apple Motion | 行为（behaviors）、参数绑定、发布参数给 FCP 模板 | **“发布参数”成模板**：Motion 做好的东西发布成 FCP 的模板，参数在剪辑软件里调——正是“转为模板”的方向（第二期的“暴露为参数”） | 基于物理的行为（有状态，违反规则 2） |
| Blender | 动作、F 曲线、驱动器、插值模式（常量/线性/贝塞尔） | 每个关键帧决定“到下一个关键帧”的插值方式；常量插值 = 保持 | 节点式驱动器（第三期再看） |
| Rive | 状态机、时间线、骨骼 | 编辑器与运行时分离、文件格式是唯一真相 | 状态机（交互式，转场用不到） |
| Lottie（及其编辑器） | 一份 JSON 描述全部图层和关键帧，播放器只解释它 | **声明式 JSON 文档 + 小解释器**：我们的动画文档就是这个思路，只是领域对象换成方块、物品、文字 | Lottie 格式本身（字段晦涩、为 AE 导出而设计） |
| Jitter | 浏览器里的轻量动效：画板、缓动预设、时间轴拖拽 | 缓动预设 + 贝塞尔自定义（复用现有 EasingField）；时间轴上直接拖关键帧 | 协作、云端（规则 10） |
| Cavalry | 过程化、复制器、行为叠加 | 第三期的“复制器”（一个图层按网格复制 N 份、按序号错开时间——方块擦除就是这个） | 求解器（有状态） |
| Theatre.js | 对象 + 属性 + 序列；“工作室”界面与运行时分包，界面只在开发时加载 | 结构上的参照：**编辑界面与运行时分离**（我们的编辑器在渲染进程，运行时是一段只用 ctx 的 JS）；“对象/属性/序列”的命名 | 代码本身（规则 7） |

结论：采用 **Lottie 式的声明式文档**（唯一真相、可读、能 diff、能被 agent 稳定地读写）+ **AE 式的编辑交互**（图层、属性菱形、自动关键帧、保持）+ **Motion 式的“发布成模板”**。

## 3. 数据格式

### 3.1 动画文档（`apps/desktop/src/shared/animation/schema.ts`，zod 校验）

```json
{
  "kind": "allay-animation",
  "formatVersion": 1,
  "name": "新动画",
  "category": "overlay",
  "duration": 2,
  "cutTime": null,
  "camera": { "type": "ortho" },
  "layers": [
    {
      "id": "block-1",
      "name": "方块",
      "type": "block",
      "block": "minecraft:grass_block",
      "size": 220,
      "props": {
        "y": { "keys": [
          { "t": 0, "v": -700, "ease": "backOut" },
          { "t": 0.6, "v": 0 }
        ] },
        "rotX": 20,
        "rotY": { "keys": [
          { "t": 0, "v": -45, "ease": "cubicOut" },
          { "t": 1.2, "v": 45 }
        ] }
      }
    }
  ],
  "sounds": []
}
```

- **坐标**：舞台设计单位（短边 1080，原点在画面中心，+y 向上，与 `ctx.stage` 一致）。旋转是度，缩放是倍数（方块、物品的实际大小 = `size × scale`），不透明度 0–1。
- **属性轨道**：常量，或按时间排好序的关键帧 `{ t, v, ease? }`。`ease` 是**从这个关键帧到下一个**的缓动：模板接口的缓动名、三次贝塞尔四元组，或 `hold`（保持，到下一个关键帧再跳）。缺省 linear。关键帧之前取第一个值，之后取最后一个值。
- **图层**：`block`（方块目录里的方块，立方体）、`item`（物品）、`text`（引擎的位图文字，`size` 是一个字体像素对应的设计单位）、`rect`（纯色矩形）。`from`/`to` 是可见区间 `[from, to)`。后面的图层画在前面。
- **音效**：`{ at, sound, gain }`，在 setup 里声明（`ctx.audio.cue`）。第一期界面上没有编辑音效的控件，只能在代码里写。
- **限制**：64 个图层、每条轨道 256 个关键帧、文本 512 KB、时长 0.1–30 秒。不认识的字段、重复的图层 id、转场缺剪辑点都拒绝，错误带路径（和 JSON 语法错误的行列）。
- **文本形式**：两格缩进的 JSON，关键帧一条一行（`serializeAnimation`）。可视化编辑每次都重新序列化；代码编辑保留用户的原文，直到下一次可视化编辑。

### 3.2 生成的模板（`compile.ts`）

```
// @allay-animation
// Generated from an animation document. Edit the animation (animation.json), not this file.
const ANIMATION = {…文档…};
async function createAnimation(ctx, doc) { …解释器（runtime.template.js 原文）… }
export default { setup(ctx) { return createAnimation(ctx, ANIMATION); } };
```

- 解释器只用 `ctx`：`resources.block(id).instanced(1)`（方块用实例，单独改不透明度）、`resources.item(id).single()`（材质复制一份再改透明度，不碰引擎缓存里的共享材质）、`text.create`、`THREE.Mesh`；`update(t)` 不分配内存。
- 文档以 JSON 字面量嵌入：JSON 是 JS 表达式的子集，文字内容里的引号、换行、`</script>` 都改变不了代码结构（T-ANIM-1 有一条专门的测试）。
- 生成的代码过 `analyzeTemplateCode`（语法、import、确定性规则 H12），与安装模板的检查相同。
- manifest：`category`、`name` 取自文档，`params: []`，`tags: ["animation"]`。

### 3.3 与工程文件的关系

- 编辑中的动画存在**工程文件**里：`.allay` 多一个可选字段 `animation`（完整的文档，zod 校验）。有它时 `template` 只是这个动画的标识（`user.<随机>.animation@0.0.0`），打开时从文档生成模板，不去模板库里找。
- 向后兼容：旧工程没有这个字段，照旧按 `template` 去模板库里找。旧版本的应用打开新的动画工程，会因为找不到 `user.….animation` 模板而提示“模板缺失”，不会误读。
- 保存的是**最后一份合法的文档**；代码视图里写到一半、解析不过的文本不进工程文件（界面上会一直显示原因）。

## 4. 与模板的关系

```
动画文档（唯一真相） ──compile──▶ manifest + template.js ──▶ 引擎 Worker（和任何模板一样）
       ▲                                     │
       │ 可视化编辑 / 代码编辑                 └──“转为模板”──▶ userData/templates/<id>/1.0.0/
                                                               manifest.json · template.js · animation.json
```

- **预览、导出都不分叉**：动画工程的“当前模板”就是生成的那份 `TemplateSource`，预览引擎、导出任务、封面、静帧接口拿到的和普通模板没有区别。
- **转为模板（手动，第一期）**：主进程自己再解析一遍文档、生成三份文件，写成一个新的用户模板（新 id `user.<6 位十六进制>.<名字>`、版本 1.0.0），写好 `template-api.d.ts` 和 `jsconfig.json`。它出现在模板库的“我的模板”里，可以用现有的“导出模板包”分享；也是普通的模板文件夹，开发模式下可以用代码编辑器或外部编辑器改。`animation.json` 留在文件夹里，为将来“从模板回到动画编辑器”做准备。
- **不反写**：转好的模板改了 template.js，不会回到动画文档（与方案 2.1 的“界面不反写代码”一致）。

## 5. 界面（第一期）

位置见 `docs/06-ui-design.md` 6.15。入口：文件菜单“新建动画”、命令面板、开发页。当前模板是动画时：

### 5.1 左栏“图层”

图层列表（最上面的画在最前面），行高 32，选中是控件高亮色；悬停显示上移、下移、删除。标题行右侧 `+` 加方块、物品、文字、色块。

### 5.2 右栏“动画”

- 没选图层：整段动画（名称、类别、时长、剪辑点、相机）和“转为模板”。
- 选了图层：内容（方块/物品选择器沿用属性面板的选择器，文字、颜色、阴影、对齐、色块大小、可见区间）、变换（八个属性，左边的菱形：实心 = 当前时刻有关键帧，空心 = 有动画但这里没有，暗 = 常量）、选中的关键帧（时刻、数值、保持、缓动——缓动用现有的 EasingField）。
- 控件和排版全部沿用属性面板（ScrubNumberField、ParamGroup、ParamRow 的网格）。

### 5.3 时间轴

替代模板的阶段时间轴（不改 `TimelineTrack`）。上面是同样的播放条；下面左侧图层名（可展开），右侧刻度、可见区间条、关键帧菱形、播放头。点刻度定位；拖菱形改时刻（一次拖动一步撤销）；菱形可聚焦，左右键挪一帧、Delete 删除。

### 5.4 代码

“动画代码”停靠面板（右栏标题行的 `</>`、视图菜单）：文档原文。开发模式开着时用内嵌的 CodeMirror（JSON 高亮、错误行内标出、Ctrl+S 立即生效），关着或模块被拆掉时是普通文本框。改完停 400 ms 解析，过了就换文档；不过就列出原因（带行列），预览保持上一份。可视化编辑改了文档时代码视图换上新文本。

## 6. 命令层（为 agent / MCP 准备，H2）

全部经注册表的 `dispatch`，入参、返回值都有 zod schema，write 命令进撤销历史并标明来源：

| 命令 | 作用 |
|---|---|
| `animNew { name? }` | 新建动画（等于新建工程） |
| `animGet → { text, revision, valid, issues }` | 读文档原文和工程修订号 |
| `animSetText { text, baseRevision? }` | 整份替换；修订号对不上就拒绝（H3） |
| `animAddLayer { type } → id` / `animRemoveLayer { layer }` | 图层 |
| `animSetKeyframe { layer, prop, t, v, ease? }` / `animRemoveKeyframe` / `animMoveKeyframe` | 关键帧 |
| `animConvertToTemplate → { id, version }` | 转为模板 |
| `animToggleCode` | 代码面板 |

这些就是将来内置 agent 或 MCP 的工具面。**这次不做 MCP**（H-MCP 未批准）；做的时候按方案 5 节的规矩接到命令层上，不新开通道。

## 7. 分期

| 期 | 内容 |
|---|---|
| **第一期（这次）** | 新建、四种图层、八个属性、关键帧（加删挪、缓动、保持）、预览、导出（走现有导出）、代码双向编辑、撤销、存进工程、手动转为模板、类型化命令 |
| 第二期 | **暴露为参数**（把某个图层的方块、文字、颜色、时长绑定成 manifest 参数，转成模板后在属性面板里调——Motion 的“发布参数”）；音效轨的界面；图表编辑器（曲线视图）；多选关键帧、复制粘贴；改参数走 `setParams` 的快速路径（现在每次修改都重新装载） |
| 第三期 | 复制器（网格复制 + 按序号错开，带种子的随机）；物品/方块的材质着色；父子层级；路径动画；从模板回到动画编辑器（读 `animation.json`） |
| 之后 | 内置 agent 或 MCP 经第 6 节的命令编辑动画（需要用户批准 H-MCP） |

## 9. 第二轮反馈（2026-11-19）

用户原话（经主控转达）：“动画编辑器我先要的效果是启动逐渐变样成专业的软件界面，部分模板的便携功能隐藏消失，被专业的功能出现替代，然后代码编辑器是另开个窗口实时双向同步查看，允许开启实时预览功能（动画在哪一帧使用了哪段代码，自动跳转标记）（允许使用别的编辑器打开，如 vs code。默认打开应用自带的）”。

### 9.1 界面原地变形

- 工作区多一个“模式”（`app/workspaceMode.ts`）：`template` 或 `animation`，跟着当前模板是不是自建动画变。界面不跳到另一页，而是在原地变：
  1. **淡出**（120 ms）：只服务模板的东西——左栏的“模板”“预设”、右栏的“属性”（模板参数）、阶段时间轴。左栏、右栏、时间轴依次错开 60 ms。
  2. **换内容**（仍是透明的）：左栏换成“图层”、右栏换成“动画”检查器，时间轴换成图层与关键帧的时间轴；时间轴的高度从 236 平滑长到 280（布局尺寸的过渡，预览区跟着平滑缩小，不跳）。
  3. **淡入**（120 ms，同样错开）。退出时反过来。
- 两种模式都有的保留不动：预览、“输出”页、“开发”页、顶栏、状态栏。
- 只改透明度和尺寸，不做位移、缩放、模糊（`docs/design-direction.md`）；“减少动效”时直接切换（`--dur-2` 为 0，模式切换不排时序）。
- 实现：注册表的面板多一个可选的 `modes`（不写就是两种都有）；左右面板只显示属于当前模式的标签页。

### 9.2 代码窗口

- **第二个窗口**，和主窗口实时双向同步。**动画文档的唯一主人仍是主窗口的工程状态**：代码窗口只显示文本、交回编辑。
  - 主窗口改了（可视化编辑、撤销、外部编辑器）→ 推整份状态（文本、解析问题、修订号、主题、语言）→ 代码窗口换上新文本（正在打字、还没交回的不覆盖）。
  - 代码窗口改了（停 300 ms 或 Ctrl+S）→ 交回文本 → 主窗口执行 `animSetText` 命令，进**同一份撤销历史**。代码窗口里的 Ctrl+Z / Ctrl+Shift+Z 不用编辑器自己的历史，而是让主窗口撤销重做。
- **安全**（`docs/01-product-architecture.md` 1.6 一条不放宽）：
  - 同一份 webPreferences（`window.ts` 的 `secureWebPreferences`：contextIsolation、sandbox、关掉 nodeIntegration、webSecurity、不用 webview）、同一个 preload；
  - 页面是 `app://renderer/code.html`，经同一个 `app://` 协议、带同一份 CSP；导航、新窗口、重定向、webview 的拦截对所有 webContents 生效（`security.ts`），代码窗口自动受管；
  - **IPC 来源白名单只认应用自己创建的那个代码窗口**：创建时按 `webContents.id` 登记，窗口关闭、渲染进程退出时注销；来源必须是这个 webContents（对象和 id 都对得上）的主框架，页面正好是应用 origin 下的 `/code.html`。**不按 URL 前缀放行**：别的窗口哪怕加载了同一个页面也不算。它**只能调一个通道** `codeWindow:send`（交回消息；页面不调别的 IPC）；其余通道只认主窗口，反过来 `codeWindow:send` 不收主窗口的调用（`ipc-guard.ts` 的 `checkCodeWindowSender`、`checkSenderFor`）。两个窗口之间不直接通信，消息都经主进程转发，两端都按 `shared/code-window.ts` 的 zod schema 校验。
- **可选模块**：编辑器仍是 `packages/optional/code-editor`。代码窗口的页面按目录发现模块，用一个只有“代码视图和文案”的受限宿主加载它，拿到它注册的代码视图。模块被拆掉时，“在代码窗口中打开”这个入口不可用（命令的可用条件），“编辑动画代码”退回主窗口里的“动画代码”面板（文本框），其余照常。
- 入口：右栏“动画”标题行的 `</>`（“编辑动画代码”，按设置决定用什么打开）、视图菜单的“在代码窗口中打开”“用外部编辑器打开”“动画代码面板”、命令面板。

### 9.3 实时预览（代码 ↔ 时刻）

- 代码窗口标题行的“实时预览”开关，默认关。开着时主窗口推播放头（约 30 次每秒），代码窗口标出**这一刻在生效的代码**：
  - 每个可见图层的开头一行（淡底）；
  - 每条有关键帧的属性所处的区间：前后两个关键帧（强调色 20% 的底），保持的区间用标记色的底；还没到第一个关键帧或已过最后一个时标出那一个关键帧；
  - 行号旁一条强调色的竖线；底部一行写出主要的那一段（“方块 · y · backOut（0–0.6 s）”）；播放头跳动时自动把它滚到中间。
- 反过来，实时预览开着时**点代码里的某处，主窗口跳到它生效的时刻**：关键帧 → 它的 t；图层 → 它出现的时刻；音效 → 它的 at；时长、剪辑点 → 那个时刻。
- **映射完全从动画文档的结构推出来**（`shared/animation/source-map.ts`）：一个记录位置的 JSON 解析给出每个值在文本里的范围（用户自己排版的也能定位），再按文档里的可见区间、关键帧时刻算出哪一段在生效。不在 Worker 里埋任何探针，画面仍是时间的纯函数（硬性规则 2）。

### 9.4 外部编辑器

- 设置“开发”页的“代码编辑器”：**应用自带**（默认，代码窗口）/ **系统默认**（系统给 .json 关联的程序）/ **指定程序**（经主进程的文件对话框选一个程序，界面上只看到文件名）。
- 外部编辑器打开的是**动画文档文件本身**：主进程把文档写成 `userData/animations/<动画的标识>.json`（应用自己的数据目录；文件名由主进程按标识决定，标识按 `user.<6 位十六进制>.animation` 校验，拼不出别的路径），然后打开它：
  - 系统默认：`shell.openPath(文件)`，只会是 .json（不对 .js 调用：Windows 上可能交给 Windows Script Host 执行，方案 2.2）；
  - 指定程序：`spawn(程序, [文件], { shell: false })`，参数数组启动，不经 shell、不拼命令行，只传这一个路径。
- 同步靠监视：外部保存了（内容与应用最后写的不同）→ 推给主窗口 → 和代码编辑同一条路（`setAnimationText`，进撤销历史）；主窗口改了 → 改写文件（防抖 300 ms，记下哈希，自己写的不回推）。
- 只在用户操作时启动外部程序，只在主进程里，不联网。

### 10.0 格式第 2 版

- `formatVersion` 升到 **2**。第 1 版的文档读入时迁移（`migrateAnimation`）：版本号改成 2，音效按序号补上 id（`sound-1`…）；第 1 版的写法在第 2 版里都合法，别的不变。更高的版本拒绝。
- 第 2 版加的东西：值可以写成 `{"$param": 键}`（绑定到参数）、顶层的 `params` 参数表、音效的 `id` / `rate` / `position`、文字图层的 `font`。
- **求值的两份实现**：编辑器里用 `resolve.ts` 的 `resolveDoc`，Worker 里用 `runtime.template.js` 的 `resolveAnimation`，规则相同（T-ANIM-11 用同一组输入核对两边逐字段相等）。

### 10.1 暴露为参数

- 能绑定的地方：图层的方块、物品、文字、颜色、字体、大小（宽、高），常量属性（没有关键帧的），某个关键帧的值，整段时长，音效。参数类型：number、duration、block、item、text、color、font、sound，与 manifest 的参数类型一一对应。
- 界面：能绑定的每一行右边一个链接按钮——“暴露为新参数”（用现在的值当默认值；数值参数给一个包住默认值的范围）、“绑定到已有参数”（只列类型对得上的）、“解除绑定”（写回参数现在的默认值）。绑定了的按钮是强调色，行里显示的是参数的默认值，改它就是改参数的默认值。整段动画的设置里有参数表：名称、默认值、数值的范围、用在几处、删除（删除时所有绑定写回默认值）。
- 新参数的键按目标取（`block`、`text`、`rotX`、`yKey`、`duration`…，重名时加数字），不按名称取（名称常是中文）。
- **时长参数**：整段时长绑定到 duration 参数时，所有时刻（关键帧、可见区间、音效、剪辑点）按“取值 ÷ 默认值”等比伸缩；转成模板后时间轴上画成一段，模板用户可以直接拖。
- **字体**：引擎只在 setup 之前载入 font 参数（含默认值）里出现的字体（4.5）。所以没有暴露成参数、但用了非默认字体的文字图层，生成 manifest 时每种字体自动加一个 font 参数（`autoFont1`…，在收起的“字体”分组里），字体才能载入。模板用户改这个自动参数不影响画面（图层用的是文档里写的字体）。
- 转成模板：manifest 的 params 就是参数表（加上自动的字体参数），属性面板照常显示；模板用户改参数，Worker 里的解释器用 `ctx.params` 求值。

### 10.2 音效轨

- 时间轴最下面一条“音效”轨：`+` 在播放头处加一个音效（默认是按钮点击声，选中后在检查器里换），标记可以拖（吸附到帧、播放头、关键帧；一次拖动一步撤销）。
- 检查器：音效（现有的音效选择器，带来源标记和中文名）、时刻、音量、速率、空间位置（开关后给 X / Y / Z，单位是格，与 `ctx.audio.cue` 的 `position` 相同）、“空间音效”的全局开关、删除。音效本身也能暴露成 sound 参数。

### 10.3 曲线视图（图表编辑器）

- 时间轴标题行的“关键帧 / 曲线”切换。曲线视图左边列出选中图层（没选时是全部图层）有关键帧的属性，点一下显示或隐藏；右边把显示的属性叠在一张图上，每条属性一种颜色（只用设计变量里已有的颜色），纵轴自动取显示的曲线的范围。
- **数值曲线**：关键帧是小方块，拖动改时刻（对齐到帧）和数值（Shift 只改数值、Alt 只改时刻；绑定到参数的值只改时刻）；选中的关键帧两侧画出它所在段的缓动的贝塞尔手柄，拖手柄改这一段的缓动（预设缓动先换成同样形状的近似贝塞尔，与精确公式差不到 0.02，见 T-ANIM-15）。弹性、回弹、保持不是一条三次贝塞尔，不给手柄。
- **速度曲线**：数值每秒的变化（数值差分），只看，不能拖。
- 框选、加选与关键帧视图共用同一份选择。

### 10.4 多个关键帧

- 点选；Shift / Ctrl 点击加选或取消；在空白处拖出框选（框碰到就算选中）；点选中组里的一个、不拖，松开时只留下它。
- 拖选中的任意一个，整组一起挪：被拖的那个对齐到帧，再吸附到播放头、没选中的关键帧、音效、剪辑点和两端（6 像素内），按住 Alt 临时不吸附；标题行的磁铁按钮是吸附的总开关。挪出时长、或和同一条轨道上没选中的关键帧重合时整组不动。
- 选中两个以上时，刻度行上画出选择的范围条，两端的手柄拖动是以另一端为中心缩放时间。
- 方向键按一帧挪（Shift 十帧）；Ctrl+C / Ctrl+V 复制、粘到播放头（剪贴板只有一个图层时粘到选中的图层，只有一条属性时粘到最后点中的属性，即跨图层、跨属性粘贴；同一时刻已有的覆盖）；Delete 删除；Ctrl+A 全选（选中图层的，没选图层时是全部）；“对齐到播放头”“对齐到帧”。这些都是带快捷键的命令，可以在设置里改键。

### 10.5 拖动的实现

- 一次拖动一步撤销：按下时记下文档，每次移动都从按下时的那份重新算（不累积取整误差），提交时是一次手势。
- 拖动的指针监听挂在 window 上（`pointer.ts`）：关键帧按时刻作 React 的 key，拖动中元素会被换掉，挂在它身上的监听会跟着没（e2e 发现的问题）。

### 10.8 图层：层级、组、复制、开关、排序（第二批）

- 图层可以有父级（`parent` 写父图层的 id）。子图层的变换接在父级后面：世界 = 父级的世界 · 自己的平移旋转缩放；父级的“大小”（方块边长、物品高度）只用在父级自己身上，不传给子图层。不透明度沿父级相乘；父级隐藏或不在可见区间时子图层也不画。
- 组（`type: "group"`）是只有变换、不画东西的图层，用来一起动一组图层。成组（Ctrl+G）在选中图层里最前面一个的位置插一个组，把选中的挂进去；解组（Ctrl+Shift+G）把子图层挂回组的父级。**组自己有变换（有关键帧或非默认值）时拒绝解组**：子图层得把组的变换乘进自己的每个关键帧，旋转加缩放时没法用 x、y、rotZ、scale 四条轨道准确表示，与其悄悄改变画面不如不做。
- 复制（Ctrl+D）连同子孙一起复制，新 id 按“原 id + 序号”取，复制品里的父子关系指向复制品。删除图层时它的子图层改挂到它的父级。
- 隐藏（`hidden`）、独显（`solo`，有任何图层独显时只画独显的和它们的子孙）、锁定（`locked`，界面上不能选中拖动、检查器只读；画面不受影响）。
- 图层面板：按树显示（子图层缩进），双击改名；拖动排序（放在某行的上半、下半，或放进组里）；多选（Shift 连选、Ctrl 加选）。时间轴的图层行也按树的顺序，可见区间两端可以拖。
- `doc.layers` 的顺序就是画的顺序（后面的画在前面），层级只由 `parent` 表示：格式不用嵌套，旧文档不用迁移，代码里也好改。

### 10.9 在预览里直接变换（第二批）

- 动画工作区里预览上盖一层：点画面选中图层（画在最前面的、可见、没锁定的），Shift / Ctrl 加选，点空白取消。选中的画外框；主选中的有四角缩放手柄（等比）和上方的旋转手柄（Shift 按 15° 吸附）。
- 拖框内移动：图层中心吸附到舞台中线、四边和别的图层的中心（6 像素内），吸住时画参考线；Alt 不吸附；时间轴的吸附开关同样管它。
- 改的是当前时刻的 x、y、scale、rotZ：有关键帧的落关键帧，绑定到参数的改参数的默认值（同检查器）。一次拖动一步撤销。有父级时换算到父级的坐标里；有路径时 x、y 是相对路径的偏移，自动朝向的角度不算进 rotZ（10.11）。
- **几何是编辑器自己算的平面近似**（`stage-geometry.ts`），不问引擎：只取 x、y、rotZ、scale 组成平面变换，z 和透视不算（透视相机下、有 z 时框会偏）；方块、物品按 rotX、rotY 算投影的外框；文字的宽高按字数估（一个字 6 × 9 个字体像素）。

### 10.10 复制器（第二批）

- 任何不是组的图层可以打开复制器（`repeat`）：网格（列 × 行，格距）、一条线（份数，每份相对上一份的位移）、一圈（份数、半径、展开角度，可以朝外转）。网格最多 256 份。
- 每一份按名次晚 `stagger` 秒播放图层自己的动画（可见区间也跟着晚）。名次：按序号、倒序、从中心向外（同样远的同一名次）、随机。
- 随机抖动（位置、旋转、缩放的幅度）和随机名次都来自 `ctx.random('repeat:<图层 id>:<seed>')`，换种子换结果，画面只取决于 t。
- 方块图层还可以给方块列表和“方块排列”：每一份放哪种方块，规则与方块擦除、方块坠落模板的“方块排列”相同（T-ANIM-26 用模板的 `arrangement.ts` 核对）。同一种方块的各份用一组实例画。
- 世界 = 父级 · 复制器偏移 · 图层自己 · 大小。子图层接在图层本身（第 0 份、不晚开始）后面，不跟着复制。

### 10.11 路径动画（第二批）

- 图层可以有一条路径（`path`）：点和每个点的入、出贝塞尔手柄（相对点的位置，不给就是直线），可以首尾相接，可以自动朝向（rotZ 加上路径的切线方向）。
- 新属性 `progress`（0–1）是沿路径走到哪里，**按长度匀速**：每段分 32 小段估长度建表，按长度比例取位置（不按参数 t，参数 t 在弯的地方忽快忽慢）。图层的 x、y 是相对路径的偏移。
- 检查器的“路径”一组：打开时给一条三个点的缓弧（以图层现在的位置为中心），并让 progress 在整段里从 0 走到 1（缓入缓出）；首尾相接、自动朝向、加一个点、删最后一个点。关掉时 progress 一起去掉。
- 预览里画出主选中图层的路径（父级坐标里，加上 x、y 的偏移）：拖点移动，拖手柄改弯度，按住 Alt 从点上拖出一对对称的手柄。一次拖动一步撤销。
- 路径几何写了两份：编辑器的 `path.ts`（画路径、算框）和 Worker 里的运行时，规则相同（T-ANIM-28 核对）。

### 10.12 形状与混合方式（第二批）

- 矩形加了圆角（`radius`，超过短边一半按一半算）；新增椭圆（`ellipse`）和线段（`line`：沿 x 长 `width`、粗 `height`，圆头或平头）。
- 填充可以是纯色或渐变（`gradient`）：线性（`angle` 度，0 是从左到右、90 是从下到上）或径向（从中心到外框边缘）。渐变画成一张 64 × 64 的 sRGB 贴图按外框铺（不用自定义着色器，色彩管理和别的材质一样）。
- 矩形和椭圆可以有描边（`stroke`），画在形状里面（外框不变），是填充上面的一个环。
- 混合方式（`blend`）：正常、相加、正片叠底、滤色，物品、文字、形状、图片都有，方块和组没有（方块用引擎的实例材质）。画面缓冲是线性、预乘 alpha 的，混合按预乘的颜色算：相加 src + dst，正片叠底 src·dst + dst·(1 − a)，滤色 src·(1 − dst) + dst；alpha 一律按普通叠加。**在透明背景上**，相加、滤色和正常差不多，正片叠底会变黑（底下没有颜色可乘）——导出透明视频时这几种模式要在剪辑软件里叠到画面上才是想要的效果。

### 10.13 图片图层（第二批）

- `image` 图层：资源栈里的贴图 ID（原版贴图 `minecraft:block/stone`、GUI 精灵 `minecraft:gui/sprites/…`）、模板包里的 `asset:` 图片，或用户选的本机图片（`file:` 引用）；铺成 `width × height` 的四边形，空的时候不画。可以打开九宫格（`nineSlice` 边框 [左, 上, 右, 下]，贴图像素；`pixelSize` 是边框一个贴图像素多大），GUI 面板、按钮拉伸时边框不变形。
- 图片可以绑定到新的参数类型 `texture`（参数的默认值只能是资源栈里的贴图或空）；转为模板后这个参数允许用户选本机图片（manifest 里 `allowFile`）。
- **本机图片**：`file:` 引用只在这次运行有效。工程保存时文档里存成空、路径记进工程文件的 `animationFiles`（图层 id → 路径），打开时重新签发引用，找不到的报告图层名（同 texture 参数的 `files`，1.9）。**转为模板时**图片复制进模板的 `assets/`（`image-<图层 id>.<扩展名>`），文档里换成 `asset:` 引用（同派生模板，4.7）；读不出的图片拒绝转换。

### 10.14 逐字动画（第二批）

- 文字图层可以打开逐字（`chars`）：每个字（空格除外）一份，摆在它在整段文字里的位置，按名次晚 `stagger` 秒播放这个图层自己的动画；位置、旋转、缩放都以每个字自己的中心为准。名次同复制器（随机名次来自 `ctx.random('chars:<图层 id>:<seed>')`）。不能和复制器同时开。最多 256 个字。
- 字的位置是量出来的：字宽、两个字之间的间隔（宽("aa") − 2·宽("a")）、空格的步长、行距都用 `ctx.text.create` 量（量完就释放）。与整段排出来的位置可能差半个字体像素。
- 多行文字：文字内容里的换行就是分行（引擎本来就按换行分行），检查器的文字框是多行的。

### 10.15 第一批遗留的两项

- 曲线视图可以让每条曲线用各自的纵轴（标题行的按钮）：每条按自己的最大最小值铺满高度；左上、左下角写的是最后点中的那条属性的范围（用它的颜色）。
- 代码窗口的实时预览也标出这一刻在生效的参数绑定（`{"$param": …}` 那一处，标签写参数名和取值）；复制器、路径整段标出。

### 10.16 命令（第二批）

图层：`animSetLayerFlags`、`animRenameLayer`、`animDuplicateLayers`、`animGroupLayers`、`animUngroup`、`animSetParent`、`animMoveLayer`、`animMoveLayerRelative`、`animSetLayerInterval`。复制器：`animSetRepeat`。路径：`animSetPath`（`path` 为 null 时去掉；可以同时换 progress 属性）。作用于选中的图层、带快捷键：`animDuplicateSelection`（Ctrl+D）、`animGroupSelection`（Ctrl+G）、`animUngroupSelection`（Ctrl+Shift+G）；Delete 也删选中的图层。形状、图片、逐字的字段走现有的图层编辑（同检查器）。
