# M6b 评审说明

**做了什么**（细节见 `docs/decisions.md` 的“M6b”）

- 引擎替每个 cue 选定音效变体（`random('sound:'+事件+':'+序号)`），写进 `AudioCue.variant`；宿主经 `resources.soundVariants` 合并各层 `sounds.json`。
- `apps/desktop/src/renderer/audio/`：预览（实时）和导出（离线）共用一份调度函数；预览跟着播放、暂停、跳转、循环、静音、cue 变化重新调度；试听；缺失音效静音并提示。
- 音效选择器：库是资源栈合并后 `sounds.json` 的全部事件，“常用”置顶、按“命名空间 · 类别”分组、可搜索、虚拟滚动，标出“未下载”“不可用”；没有素材时为空并引导。
- 下载缓存的原版层：常用事件在“下载原版资源”时取回；其余在试听、选中、导出前确认时按需经 `fetchObject` 取回；导出前有没取回的会停一步提示，导出中途不联网。下载说明文案已改。
- 导出：离线混音 → `export.writeAudio` → 主进程落盘后启动 FFmpeg；ProRes 带 `pcm_s16le` 音轨，PNG 序列另存 `name.wav`；没有能出声的 cue 时不加音轨。
- 引擎补强：`BlockHandle.faceTexture(face)`，T3/T5 改用；着色器编译失败记成模板警告。

**和规格不同的地方**：音频样本数取“帧数 / 帧率 × 48000”（与视频等长）；离线混音逐个声音渲染再相加（同一节点多路输入的求和顺序在 Chromium 里不固定，两次混音会不同）；试听不受静音开关影响；有音轨的导出在 `writeAudio` 之后才启动 FFmpeg；导出对话框多了一步“取回音效”；非常用事件只显示 ID（不读游戏的字幕文件）；`allay:whoosh`（T3 默认）没有原版来源，默认静音并提示。

**没验证的**

- **没有人真的听过**任何一个声音：只在静音的隐藏窗口和离线上下文里核对了调度状态、样本数据和 ffprobe。音质、音量、与画面的听感同步、停止时有没有爆音，都要人在可见窗口里听。
- 带音轨的 ProRes 没在真实剪辑软件里打开过。
- 真实 Mojang 服务器上的音效下载（下载时和按需）没跑，只对本机假服务器测过；“估计不到 2 MB”没核实；本机游戏资源索引里的音效没在这台机器上试过（本机 `.minecraft` 没有 `assets/`）。
- 选择器在上千个原版事件下的手感（滚动、搜索速度）只用测试资源包的几个事件看过。
