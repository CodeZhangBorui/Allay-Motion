# M3 模板系统 评审说明

**做了什么**：`template-sdk` 有了完整的 manifest schema、15 种参数类型的校验与清洗（引擎和界面共用）、迁移框架、派生与预设。主进程能读取、校验（4.8 第 1–3 步，zip 复用资源包的防护）、安装、卸载、导出模板包，存取预设；IPC 有 `templates`、`presets` 命名空间。渲染进程安装时在杂务 Worker 里试运行并做确定性自检。`pnpm templates:build` 用 esbuild 把内置模板打成 `.allaytpl`，应用从 `resources/templates/` 装载，与用户模板同一条路径。M1 的临时模板换成了包含全部参数的正式 T1，左栏是一个最小的模板列表。

**截图**（资源栈里只有测试脚本生成的纯色假原版层，没有原版贴图；`pnpm review:m3` 生成）：`m3-t1-in.png`（T1 默认参数，进入阶段）、`m3-t1-cut.png`（剪辑点）、`m3-t1-flat-diagonal.png`（平面、对角线、三种方块）。`--real` 用本机游戏截的同样三张在被忽略的 `out/`，不提交。

**和规格不同的地方**（详见 `docs/decisions.md` 的 M3 小节）：
- T1 的进入、退出阶段首尾各让出一帧、剪辑点前后各留一帧（解决 M1 发现的首帧有内容的问题）。
- 引擎的 sceneRT 从 MSAA 4× 改成 2×2 超采样；InstancedMesh 的包围球固定在原点。两处都是 T-TPL-3/4 查出来的真实不确定性，根因和证据写在 decisions 里。
- IPC 多出 `commitInstall`、`cancelInstall`、`saveDerived`；来源登记多出 `origin: rendered`（渲染基准图）。
- 封面与悬停预览（4.8 第 5 步）、属性面板、另存为模板的弹窗、预设界面留给 M4；内置模板启动时不试运行。

**没验证的**：只在这台机器（RTX 5070 Laptop，D3D11）上跑过，没在软件渲染或别的显卡上跑 T-TPL-5（判定按 4.11 自动放宽到 4/255，但没实测）；主进程对话框的安装、导出、预设导入导出没有 e2e（服务方法有单元测试）；超采样对预览帧率的影响没有量；导出结果没有在真实剪辑软件里看过。
