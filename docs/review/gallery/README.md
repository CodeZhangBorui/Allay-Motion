# 模板库（一百个模板）的评审截图

`pnpm review:gallery` 生成（先 `pnpm build`），见 `scripts/review-gallery.ts` 和 `docs/decisions.md`“模板库撑到一百个模板”。

这一层的截图用的是测试脚本生成的**假原版层**（纯色色块），里面没有任何 Mojang 素材，可以提交。封面因此大多是平涂的色块或几乎透明的界面元素，**不是**真实效果。用本机游戏文件截的那一份在 `out/`（被 git 忽略），要看真实贴图下的封面时在本机生成：

```
pnpm review:gallery --game "<.minecraft 目录>" --version 26.2
```

一百个模板的场景用 `tests/e2e/template-library.ts` 现拼：现有 17 个内置模板加 83 份复制品（改了 id、名字、分组和类别），名字后面的三位数是复制品的编号。每个场景两张：整个窗口（1440 × 900，截图是设备像素）和左栏原尺寸（`.left.png`）。

## 要人判断的

1. **信息密度**：两列、16:9 缩略图、名称和时长一行，段头 32 px。一百个模板时一屏能看到 10–12 张。够不够，要不要在宽一些的左栏里放三列。
2. **分组用下拉而不是一排标签**：九个组名放成标签要占两三行，最窄的窗口里卡片只剩一行；下拉只占一行，代价是要多点一下。段头已经按组分好了，平时不用打开下拉也能看出分组。是否接受。
3. **段头吸顶**：滚动时当前组的名字一直在顶上，贴顶时下面一条 1 px 分隔线。是否需要可以折叠的段头（现在不能折叠）。
4. **排序**：组的顺序同目录（方块、物品与实体、原版界面……），组内按名称（中文按拼音，汉字排在拉丁字母前面）。用户可能更想要“常用的在前”或者“新的在前”，这一版没做。
5. **英文、最窄的左栏**：类别标签折成两行，“Mine”单独一行；名称大多截断（提示里有全名）。可以接受，还是要在窄的时候换一种排法。
6. **封面生成失败的样子**：凹槽底加一个第三级灰的“图片坏了”图标，原因在鼠标停留的提示里。是否要更明显（例如警告色的角标）。
