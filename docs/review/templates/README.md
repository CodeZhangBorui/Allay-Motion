# 内置模板的评审截图

`pnpm review:templates`（`scripts/review-templates.ts`）用一条命令拿到“某几个内置模板在某个游戏版本的真实原版素材下”的画面和一份装载报告，给做模板的会话自己看，也给人看。每一批模板交付前都要用它看过（`docs/template-catalog.md` 第 2 节“没有原版素材、素材版本不对时”“对照游戏文件核对”两组）。

**输出含原版贴图和字体的派生图像。**只写进被 git 忽略的 `docs/review/templates/out/`（或 `--out` 指定的目录），不提交、不外传（`AGENTS.md` 硬性规则 1）。提交的评审结论里只写文字，不贴这些图。

## 先做什么

1. `pnpm build`。工具会核对构建产物：应用（`apps/desktop/out/`）比源码旧、要截的模板（`resources/templates/*.allaytpl`）比模板目录或 `packages/templates/_lib` 旧、或者还没构建时，直接报错退出，不会悄悄用旧产物。
2. 第一次在这个检出里启动 Electron 之前：`pnpm exec tsx scripts/ensure-electron-dist.ts`（下载一次 Electron 二进制，之后不联网）。
3. 抬头显示类的帧大部分是透明的，一张 1080p 的 PNG 平均几十 KB；11 个模板带全部预设一轮约 80 组、500 张、连联络图约 20 MB，在 26.2 上跑完约 3 分钟。系统临时目录（`TEMP`）要有空间放临时的用户数据目录。

## 用法

```bash
pnpm review:templates --game "<游戏目录>" --version 26.2 --presets boss-bar hud-status
```

```bash
pnpm review:templates --no-assets --presets
```

| 选项 | 说明 |
|---|---|
| `--game <目录> --version <版本目录名>` | 原版来源：本机游戏目录（`.minecraft`）和 `versions/` 下的版本目录名，按“本机游戏”这一种来源接进资源栈。和 `--no-assets` 二选一 |
| `--no-assets` | 不接任何原版来源，看没有素材时的样子 |
| `--out <目录>` | 输出目录，默认 `docs/review/templates/out/<版本目录名或 no-assets>/`（`--lang en` 时加 `-en`） |
| `--presets` | 除默认参数外，每个自带预设也截一组。预设里写成双语的文字按 `--lang` 取，和应用套用预设时一样 |
| `--cover` | 另截一张封面：320 × 180、默认参数，取法和模板库的封面相同（剪辑点；没有剪辑点时是前 4 秒的中间一帧）。看“叠加层默认的大小在封面里看不看得出是什么”（`docs/template-catalog.md` 第 2 节）用 |
| `--at <时刻,…>` | `50%`（时长的比例）、`1.5s` 或 `1.5`（秒）、`f30`（帧号）、`cut`（剪辑点）、`first` / `last`（首末帧附近：离两端时长的 3%，至少 2 帧）。默认 `first,20%,40%,60%,80%,last`，模板有剪辑点时再加 `cut`。帧号按 round(t × fps) 取，落在同一帧的只截一次 |
| `--aspect <画幅,…>` | `16:9`、`9:16`、`1:1` 或 `all`，默认只截 `16:9`。经界面右栏“输出”页的分辨率切换（和用户同一条路），切完核对工程的输出 |
| `--lang <zh-CN\|en>` | 界面语言，默认 `zh-CN`。文字参数的默认值跟着变：中文下能同时看到 Mojangles 的英文数字和 Unifont 的中文，英文下全是 Mojangles |
| `--set <参数=值>` | 盖在每一组参数（默认参数、各个预设）和封面上的参数，可以给多次：`--set guiScale=7 --set hold=2`。值按 JSON 读（`7`、`true`、`"文字"`、`{"family":"embedded:uniform"}`），读不成时当文字（`--set style=toast`）。用来比较几个候选值，比如定默认的 `guiScale` 时配 `--cover` 截几遍。默认的输出目录名后面加上 `+参数=值`；同一个目录只放同一组 `--set` 的结果 |
| 模板名 | `packages/templates` 下的目录名（也可以写完整 id）；不给就是全部有 `manifest.json` 的内置模板 |

退出码：0 完成；2 参数不对、没有构建或构建过期；3 原版来源接不进资源栈；4 有模板装载或渲染失败（截图和报告照样写出）。

同一个输出目录只放同一个来源、同一种语言的结果。再截一次时，这次截了的模板整条替换，没截的保留（报告里每个模板有自己的 `capturedAt`）；输出目录不空、却不是这个工具写的，工具拒绝写入。

## 它做了什么

1. 在系统临时目录里建一个用户数据目录，写一份设置：首次启动引导和新手引导算走过、界面语言、自动更新关掉，资源栈里只有给定的那一个原版来源（或者什么都没有）。用完删掉。
2. 后台启动已构建的应用：窗口不显示；Mojang 的下载地址指到 `127.0.0.1:9`（不通，保证不联网）；探测本机游戏时不看 `%APPDATA%\.minecraft`，资源栈里只会有设置文件里给的那一层。
3. 等资源栈探测完，核对确实接上了那一层原版来源（`--no-assets` 时核对资源栈里只有内置层）。没接上就报错退出，并列出现在的层、原版基底、问题和打不开的来源，不会截一堆占位图还当成功。
4. 逐个模板、逐组参数（默认参数加自带预设）：经测试钩子选中模板，等预览装载完（就绪、出错、崩溃、无响应四种结果都记下），按时长选好时刻，再经测试钩子 `reviewFrames` 在一个新的杂务 Worker 里装载同一个模板、同一组参数，渲染这些时刻所在的帧。这是导出和封面用的同一条静帧路径（输出分辨率、直通 alpha、不加运动模糊），和预览是同一份引擎代码；不截预览画布，所以画面不受窗口大小和界面背景影响。
5. 写每一帧的 PNG、每个模板每种画幅一张联络图和一张细节图、`report.json` 和 `index.html`。每截完一个模板就更新一次报告和索引，中途停下也能看已经截好的。

## 输出

```
out/<版本目录名>/
  index.html                         所有图按模板列出：封面（--cover 时）、联络图、细节图，逐帧的缩略图标着参数组和时刻
  covers.png                         --cover 时：这次截的模板的封面拼在一起，原大
  report.json                        装载报告（见下）
  <模板名>/cover.png                  --cover 时：这个模板的封面（320 × 180，直通 alpha）
  <模板名>/contact-16x9.png           联络图：每行一组参数、每列一个时刻，帧缩小到 1/4 叠在棋盘格上，每格上面标着时刻和帧号
  <模板名>/detail-16x9.png            细节图：所有帧不透明部分的外框（四周留 8 像素）裁出来并排；小的放大 2–3 倍（最近邻），大的最多缩到 1/2
  <模板名>/16x9/<参数组>/01-first.png  每一帧：输出分辨率、直通 alpha（透明的地方在看图软件里可能显示成白色，看联络图或 index.html）
```

`report.json` 每组参数一条记录（`templates[].runs[]`），要看的字段：

| 字段 | 内容 |
|---|---|
| `preview` | 预览装载的结果：`status`（`ready`、`error`、`crashed`、`unresponsive`、`timeout`）、警告、出错信息 |
| `warnings` | 截图那次装载的警告：缺字形（`text: N character(s) have no glyph in any font`）、字体不可用、不带 `optional` 的缺失贴图、着色器编译失败等 |
| `missingTextures` | 模板向资源栈要过、资源栈里没有的贴图 ID。**可选贴图（`optional`）缺失时引擎不记警告，只能从这里看出来**。按“新路径 → 旧路径”试的模板，缺了新路径、取到了旧路径是正常的：对照 `foundTextures` 看最后用的是哪一张 |
| `foundTextures` | 要过且拿到了的贴图 ID |
| `fonts` | 要过的字体；`skipped` 是资源栈里缺的提供器（例如缺 unifont 的 zip） |
| `sounds` | 要过的音效事件和有没有 |
| `engineLog` | 引擎经宿主日志报的消息：贴图解码失败、动画元数据和图片不合（当静态图画）、渲染时才出现的警告 |
| `console` | 这一组期间页面控制台的警告和错误 |
| `error` | 装载或渲染失败的原因 |
| `params` | 选中后工程里的完整参数（清洗过、补了默认值），看文字参数实际是什么 |
| `shots[]` | 每一帧的时刻、帧号、文件、`coverage`（不透明像素的比例，0 是全透明）、`bbox`（不透明部分的外框） |

报告顶部是来源（游戏目录、版本目录、资源栈里那一层的 id、资源包格式号、有没有资源索引）、资源栈的全部层、构建（提交和应用的构建时间）。`index.html` 的开头汇总了所有缺失的贴图 ID 和是哪些模板、哪组参数要的。

## 版本目录名

`--version` 给的是 `versions/` 下的目录名，原样用。应用认得带空格、括号、中文的目录名（PCL 等启动器给装了加载器的版本起的 `1.20.1-Fabric 0.19.3`、`1.21.8-Fabric_0.17.3(生电)` 这类，规则见 `docs/03-assets.md`），只要目录里同名的 jar 是完整的原版客户端。以前应用只认字母、数字、点、下划线、连字符，工具为此有过一个 `--mirror`（在临时目录里建镜像接入），应用改了之后去掉了，再给会报用法错误。

工具先用应用自己的 `listVersions` 和 `checkClientJar` 核对这个目录，认不了时说清是哪一步不行：游戏目录下没有 `versions`、没有这个版本目录（列出有 jar 的）、没有同名 jar、版本 JSON 读不了或者缺 `type`、`releaseTime`、jar 不是完整的原版客户端（里面没有 `assets/minecraft/`，只装了加载器的版本目录常是这样，换成它继承的那个原版目录）、jar 打不开。

## 每一类模板该看什么

先看 `index.html` 开头的汇总：有没有出错的组、有没有警告、缺了哪些贴图 ID。然后逐个模板看联络图（整体位置、时序）和细节图（贴图、字体、像素），有疑问的帧点开看原图。同一个模板至少看三种情况：最新的正式版、旧一点的版本（贴图路径或画法变过的那几个版本，见模板文档第 4 节）、`--no-assets`。

**所有模板都要看的**

- 首末帧附近（`first`、`last`）在淡入淡出，不是突然出现；`coverage` 为 0 的帧在索引里标着“全透明”，除了刻意留空的时刻都不该有。
- 报告里没有出错、没有意外的警告。缺字形的警告说明默认文字里有字体覆盖不到的字符。
- 文字：Mojangles 的英文和数字、Unifont 的中文，两者混排时基线对齐、宽度合理；阴影或描边的有无和游戏里那一处一致；颜色对。
- 封面（`--cover`）：320 × 180 下看得出是什么，不是一片空白或者一小团看不清的东西。
- `--no-assets` 下：结构还在（面板、文字、动作都对），贴图换成同样位置和大小的纯色块，文字是内嵌 Unifont，不报错，不是一片占位图。

**原版界面还原（C 组：抬头显示、容器界面、提示框等）**

- 位置：按界面像素对齐（一个界面像素是 `guiScale` 个设计单位，界面里的东西应该落在这个格子上）；相对屏幕边缘或中心的偏移、行距、间距、对齐方式和游戏一致。用 `--aspect all` 看竖屏和方形下是否整体缩小而不出画。
- 贴图：是不是该用的那张（对照报告的 `foundTextures`）；没有占位图；九宫格的边没有被拉花；进度条是裁切不是压扁；带 `.mcmeta` 动画的贴图在几个时刻上确实在换帧；旧版本素材下退回旧图集时裁的区域对。
- 动画时序：进度变化、闪烁、消息出现和消失落在模板文档写的时刻上；用 `--at` 把关键时刻（例如变化开始、闪烁的亮暗两帧）单独截出来。
- 版本差异：模板文档第 4 节说某个版本有或没有的贴图，和报告的 `missingTextures` / `foundTextures` 一致；缺了的时候画法和文档写的退路一致。

**转场（A、B 组和其他有剪辑点的）**

- `cut` 那一列完全不透明，盖满整个画面（三种画幅都看）。
- 方块、物品的贴图是选中的那一个，朝向和光照合理；镂空贴图下面垫了底。
- 进入和退出两段的运动连贯，`20%`–`80%` 几列能看出运动的方向和节奏。

**粒子、天气与屏幕效果（D 组）**

- 粒子贴图的帧序列在走（几个时刻的粒子样子不同），颜色和染色合理，数量和分布不是一团。
- 没有素材时粒子换成纯色块后仍然看得出效果。

**文字与字幕条、频道包装（E、F 组）**

- 排版：对齐、换行、长文字的缩小；中英文两种语言都截一遍（`--lang en`）。
- 字体参数换成别的字体族时报告里没有“字体不可用”的警告。

**像素与着色器风格（G 组）**

- 报告里没有着色器编译失败的警告（`warnings` 和 `engineLog`）；几个时刻的画面确实在变。

## 看不出的

- 声音：工具只记音效事件在不在（`sounds`），不放、不检查时刻。
- 和游戏逐帧对照：工具只出模板的画面，游戏里的样子要人自己截来对。
- 剪辑软件里的样子：这里的帧是引擎直接给的 RGBA，不经过 FFmpeg 编码，色彩和透明通道的导出问题看不出来（`docs/05-export.md`）。
- 运动模糊：截图不加运动模糊，和关掉高质量预览的样子一样。
