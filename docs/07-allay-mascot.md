# 07 悦灵：形象与动效系统

包：`packages/mascot`（模型、烘焙脚本、图集、React 组件）。

悦灵在这个应用里有三个身份：图标、加载与反馈的载体、品牌配色的来源。它不是贴在角落的装饰。

## 7.1 角色设定

游戏里的悦灵会帮玩家**取东西、送东西**，听到音乐会**跳舞**。应用里沿用这两点：

- 应用在替用户干活时（加载素材、重建缩略图、导出），悦灵出来“取”和“送”。
- 活干完了，它把结果“送到”，然后跳一小段舞。
- 没活干的时候它不出现。

## 7.2 使用原则

| 要 | 不要 |
|---|---|
| 只在应用正在工作或有东西交付时出场 | 在空闲界面上常驻、游荡、卖萌 |
| 同一时刻全身形象最多一只（顶栏的头像不算） | 多只同屏 |
| 所有悦灵图层 `pointer-events: none`，不拦截任何点击 | 遮挡主要控件，或在用户拖滑块、拖时间轴时出现 |
| 工作结束后在 300 ms 内退场 | 让用户等它演完 |
| 预览正在播放时不进入预览画布区域 | 盖住用户正在看的画面 |
| 尊重“减少动效” | 在减少动效时仍然飞来飞去 |

## 7.3 形象资产

### 来源规则（硬性）

悦灵的模型和贴图**由本项目自行建模、自行绘制**：参考的是“大方头、小身体、细手臂、背后一对薄翅、通体青蓝”这些特征，而不是任何现成的文件。不得使用从游戏 jar、官方渲染图、官方动图、Wiki 图片中取得的任何像素或模型数据。

注意：自绘只解决了“不分发官方文件”这一个问题。用游戏里的角色做产品的图标和品牌，本身就在 Mojang 使用准则限制的范围内，是否这样做要由人决定，见 `09-compliance.md` 的 H-BRAND。在得到确认之前，照本文实现，但不要对外发布。

品牌资产全部集中在 `packages/mascot`，应用其余部分只通过组件接口使用它，日后需要更换形象时只动这一个包。

### 模型

一个由几个长方体组成的小模型，定义在 `packages/mascot/model/allay.model.ts`。单位是“模型像素”。

| 部件 | 尺寸（宽×高×深） | 说明 |
|---|---|---|
| 头 | 5×5×5 | 正面两只深色眼睛，各带一个高光像素 |
| 身体 | 3×4×2 | 上宽下窄，下端贴图渐变到透明，没有腿 |
| 手臂 ×2 | 1×3×1 | 微微前伸，像捧着东西 |
| 翅膀 ×2 | 0.5×5×4 | 贴在背后，半透明 |

贴图是一张自绘的 32×32 像素图，用代码里的字符网格加调色板生成（`allay.skin.ts`），输出 PNG。调色板：

| 用途 | 色值 |
|---|---|
| 高光、翅膀 | `#C2F2F8` |
| 亮面 | `#9EEDFB` |
| 主体 | `#52CFF3` |
| 暗面 | `#1B92C2` |
| 最深的阴影 | `#085B87` |
| 眼睛 | `#0C263A` |
| 眼睛高光 | `#F2F4F6` |

尺寸和配色是起点，实现者可以为了好看做调整，最终样子要经过人工确认（见 7.10）。

### 动作

全部是程序化的、时间的周期函数，首尾必须无缝。

| 动作 | 时长 | 内容 |
|---|---|---|
| `hover` | 1.5 s（45 帧） | 上下浮动；翅膀以 4 Hz 扇动 ±22°；手臂轻摆；身体小幅左右转 |
| `fly` | 0.8 s（24 帧） | 身体前倾 18°；翅膀以 7.5 Hz 扇动 ±32° |
| `dance` | 2.0 s（60 帧） | 绕竖轴转一整圈，同时左右摇摆两个来回，手臂上举 |
| `sad` | 1.0 s（30 帧） | 低头，翅膀下垂慢扇，缓慢浮动 |

捧着东西时不换动作，只是把物品图标画在手部锚点上。

### 烘焙

悦灵的图集**由应用自己的引擎渲染出来**：把模型写成一个不在模板库里显示的内部模板 `allay.internal.mascot`（参数是动作名），走导出管线渲染透明 PNG 帧，再拼成图集。这同时也是对导出管线的一次实战检验。

- 命令：`pnpm mascot:bake`。
- 相机：正交，朝右，绕竖轴约 −28°、俯角约 8°。带面明暗。背景透明。
- 30 fps。两套帧尺寸：288×288 和 96×96。
- 输出到 `packages/mascot/assets/`，并提交进仓库（日常构建不需要重新烘焙）：
  - `allay-288.png`、`allay-96.png`：13×13 的网格图集，共 159 帧。
  - `allay.atlas.json`：

    ```json
    { "fps": 30, "columns": 13,
      "clips": { "hover": { "start": 0, "count": 45 }, "fly": { "start": 45, "count": 24 },
                 "dance": { "start": 69, "count": 60 }, "sad": { "start": 129, "count": 30 } },
      "handAnchor": [[0.62, 0.58, -8], "…每帧一项：x、y（占帧边长的比例）和旋转角度"] }
    ```
  - `allay-head-{16,20,24,32,48}.png` 及对应的闭眼版本：正面头像，用于顶栏和小尺寸场合。
  - `icon.ico`（以及日后的 `icon.icns`）：头像放在圆角方形底板上，底板是 `#2072D5` 到 `#52CFF3` 的 135° 渐变，由 `scripts/make-icons.ts` 生成 16–1024 各尺寸。
  - `docs/review/mascot-contact-sheet.png`：所有动作的关键帧排在一张图上，供人工确认。
- 显示尺寸小于 28 px 时一律用头像，不用全身图集。

## 7.4 组件

```tsx
// 一只悦灵。只负责画当前帧，不负责移动。
<Allay clip="hover" size={72} facing="right" carry={<ItemIcon id="minecraft:diamond_block" />} glow />

// 包住一块带骨架的区域：加载超过 delay 才出现，出现后至少停留 minVisible。
<AllayLoader loading={isLoading} delay={180} minVisible={500} label={t('loading.templates')}>
  {isLoading ? <TemplateGridSkeleton /> : <TemplateGrid />}
</AllayLoader>

// 导出进度。
<AllayProgress value={0.42} phase="rendering" carry={<ItemIcon id={primaryBlockId} />} />
//   phase: 'rendering' | 'muxing' | 'done' | 'error' | 'canceled'

<AllayEmpty title="…" description="…" action={<Button>…</Button>} />   // 空状态
<AllayHead size={20} />                                                // 顶栏头像，偶尔眨眼
```

实现要点：

- `Allay` 用一个 `<canvas>` 从图集里 `drawImage` 当前帧。图集解码成 `ImageBitmap`，全应用只解码一次。按 `size × devicePixelRatio` 在 96 和 288 两套里选不小于所需的那套。
- 动作的帧步进是 30 fps；位移是独立的，跟随显示器刷新率。两者解耦。
- 位移只改 `transform`。一个区域内的所有运动由一个 `requestAnimationFrame` 循环驱动，循环里不读取布局。
- 朝向用水平翻转实现，转身用 140 ms 完成。
- `glow` 是 CSS `drop-shadow`，不烘进图集。界面禁止外发光（`06-ui-design.md` 6.1），`glow` 留在接口里但不画（`docs/decisions.md` 界面重设计）。

第 9 项是唯一常驻的，而且只是一个 20 px 的头像。

第 12、13 项是 7.2“没活干时不出现”的例外（用户要求，2026-11-14，`docs/decisions.md` 新手引导）：这两处悦灵本身就是在带路，引导结束就退场；仍然 `pointer-events: none`、同一时刻只有一只、尊重减少动效。

## 7.6 四段重点编排

### A. 骨架屏上的飞舞（最重要的一段）

设区域宽 `w`、高 `h`，中心 `(cx, cy)`。悦灵尺寸 `S = clamp(h × 0.22, 48, 96)`。

- **进场**：加载持续 180 ms 后，悦灵从区域左侧外面飞入，320 ms 到达路径起点。
- **路径**（`τ` 是进场后的秒数）：
  - `x(τ) = cx + (w/2 − 24 − S/2) × sin(2π τ / 3.6)`
  - `y(τ) = cy + min(h × 0.18, 40) × sin(2π τ / 2.3 + 0.6)`
  - 朝向取 `dx/dτ` 的符号；倾斜角与水平速度成正比，不超过 ±10°。
  - 水平速度大时用 `fly`，接近折返点时切到 `hover`。
- **光**：界面重设计后去掉（界面禁止外发光和渐变，`06-ui-design.md` 6.1）。骨架本身不做横扫的高光，只有很轻的呼吸（不透明度在 0.9 和 1 之间，周期 1.6 s）。
- **拖尾**：一个固定 6 个元素的池子，每 80 ms 在悦灵尾部放出一个 4×4 px 的 `--allay-light` 方点，420 ms 内淡出并缩小。
- **退场**：内容就绪且已显示满 500 ms 后，悦灵用 260 ms 从较近的一侧加速飞出。与此同时内容项依次淡入并上移 8 px，顺序按它们与悦灵飞出位置的水平距离，间隔 24 ms，看起来像是悦灵边飞边把东西放下。
- 加载不到 180 ms 就结束的，悦灵和骨架都不出现。

### B. 导出进度

- **渲染帧**：一条进度条。悦灵悬在进度条前端的上方，捧着用户这个转场用的方块（取 `blocks` 的第一项；模板没有方块参数时捧一个胶片图标）。水平位置用弹簧跟随进度，不抖动。进度条前端有少量拖尾方点。
- **封装**：进度到头后，悦灵飞向进度条右端的文件图标，把手里的东西放进去，图标弹一下。
- **完成**：`dance` 播一遍（2 秒），然后回到 `hover`。标题用像素字。
- **失败**：`sad`，手里的东西掉下去淡出。
- **取消**：悦灵向上飞出。

### C. 启动画面

- 一个 420×260 的无边框小窗，底色 `--background`，圆角 12。
- 悦灵捧着一个方块从左侧飞入，在中央悬停；下方是像素字的 “Allay Motion” 和小一号的“悦灵动画”，再下面一行状态字。
- **只用静态 HTML、CSS 和图集实现**（CSS `steps()` 播帧，关键帧动画做飞入），不依赖主应用的脚本，这样进程一启动就能显示。
- 至少显示 600 ms。主窗口就绪后启动画面淡出。

### D. 拖放接收

- 文件拖进窗口：界面压暗，可放区域出现虚线框，悦灵在中央 `hover`，下面一行字“放这里”。
- 放下且文件有效：悦灵捧起这个包的图标，飞到它的归宿（资源包飞向顶栏的素材按钮，模板包飞向“我的”标签），放下，目标弹一下，同时出一条通知。
- 文件无效：`sad` 播 0.6 秒，出错误通知。

## 7.7 品牌母题

悦灵之外，另有三个从它身上来的视觉元素。它们用得很省：

| 母题 | 用在哪里 |
|---|---|
| **强调色天蓝**（平涂，不发光） | 焦点环、选中的模板缩略图外框、播放头、进度条 |
| **像素方点拖尾** | 只在悦灵飞行时和导出进度条前端 |
| **像素字** | 只在模板画面里（没有原版层时的兜底字形）；界面不用像素字（`06-ui-design.md` 6.2） |

## 7.8 文案

- 状态文案短而具体，说清楚正在干什么。可以提到悦灵，但一处只提一次。
- 错误信息里不出现悦灵，不卖萌，只说发生了什么、怎么办。

| 场景 | 中文 | English |
|---|---|---|
| 加载模板库 | 正在取模板… | Fetching templates… |
| 重建封面 | 正在用新素材重画封面… | Redrawing covers with the new assets… |
| 装载模板 | 正在搭场景… | Setting the scene… |
| 导出中 | 正在渲染第 {i} / {n} 帧 | Rendering frame {i} of {n} |
| 导出完成 | 导出完成 | Export complete |
| 拖放 | 放这里 | Drop it here |
| 资源包已添加 | 已添加资源包“{name}” | Added resource pack “{name}” |

## 7.9 减少动效与性能

- “减少动效”开启时：没有飞行、没有拖尾、没有内容上移。骨架静止，悦灵以 `hover` 的第一帧静止显示在区域中央偏左，旁边是状态字。导出时悦灵静止在进度条前端。启动画面是静态的。
- 性能预算：飞舞期间，主线程每帧用于悦灵的时间 p95 不超过 1 ms；`requestAnimationFrame` 回调里零次强制重排。

## 7.10 验收

| 编号 | 内容 | 判定 |
|---|---|---|
| T-ALY-1 | 图集完整性 | 帧数与 `atlas.json` 一致；每个动作“末帧到首帧”的像素差不超过该动作相邻帧差中位数的 1.5 倍 |
| T-ALY-2 | 加载时序：分别模拟 100 ms、300 ms、3 s 的加载 | 100 ms：悦灵和骨架都不出现；300 ms：出现并至少停留 500 ms；任何情况下就绪后 300 ms 内退场完毕 |
| T-ALY-3 | 端到端脚本跑完一整套操作 | 任意时刻 DOM 里的全身悦灵不超过一只 |
| T-ALY-4 | 开启 `prefers-reduced-motion` | 悦灵相关元素上没有 transform 动画 |
| T-ALY-5 | 飞舞时在悦灵所在位置点击 | 点击落到下面的元素上 |
| T-ALY-6 | 性能跟踪 | 满足 7.9 的预算 |
| T-ALY-7 | 仓库扫描 | `packages/mascot` 里的每个图片文件都能由脚本从源码重新生成 |

**人工确认点 H-ALY**：实现者交出联络图（contact sheet），以及 A、B、C 三段编排各一段 10 秒的录屏。人确认形象和动效可以接受之后，才把悦灵接到应用的各个位置。
